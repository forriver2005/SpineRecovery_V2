# 死虫交付包：独立游戏场景

新增场景：`Assets/Scenes/DeadBug_RingSkinC_Delivery.unity`。

在 Unity 中打开该场景运行，选择难度后开始。原死虫游戏的动作选择／暂停菜单也新增了「死虫新评分场景」按钮。新场景支持暂停、继续、结束并查看本次成绩、返回原死虫游戏；切换游戏会结束当前训练。

场景复制自现有 `DeadBug_RingSkinC_Recorded.unity`，沿用星空圆环、四个肢体文字与颜色。交付包的评分、约束、姿势测量、录制教练和输入数据接口均放在独立的 `DeadBugDelivery` 命名空间。原有游戏场景、共享脚本以及此前完成的鸟狗迁移目录保持不变。

## 已接入内容

| 模块 | 用途 |
| --- | --- |
| `DeadBugHoldScorer` | A/B 状态识别、稳定保持计时、扣分、每轮最高分结算 |
| `DeadBugPose` | 测量活动手腿、另一侧准备姿势、躯干及大小腿方向 |
| `DeadBugAnatomicalConstraint` | 关节范围、分部位角速度、骨长／缩放、无效旋转保护 |
| `RecordedDeadBugCoachMotion` | 录制动作及其解剖镜像，独立循环演示两侧 |
| 交付包 `AvatarMotionSource` | 保留逐帧骨骼包计数、输入有效性与冻结接口 |
| `DeadBugVmcSourceBridge` | 在接收器更新后、约束和评分前，写入当帧输入；没有包时写零 |
| `DeadBugDeliveryGame` | 开始／难度／暂停／成绩、双模型预览、圆环 HIT／MISS 与实时分项 |

接收器使用当前项目的 EVMC4U/uOSC，监听 UDP **39539**，只同步骨骼旋转，启用交付包设置的旋转滤波（0.7）。不从发送端覆盖根位置、根旋转、根缩放或骨长。需要由发送端向运行游戏的机器发送有效 Humanoid VMC 数据。

本项目原有输入接口会缓存上一帧骨骼包数量，不能直接表达交付包要求的「没有新包就不累计」。因此本模块保留交付包自己的接口，通过独立 LateUpdate 接收桥逐帧写入计数，包括零计数；没有覆盖共享 `AvatarMotionSource`，也没有为迁移改变评分算法。

## 动作与计分

**A：仰卧，双臂竖直伸直，大腿上举，小腿近水平，髋膝约 90°。手脚平放地面不算 A。**

流程为 A → 对角手腿向远端伸展 → B 保持 → 四肢回到 A。右臂＋左腿或左臂＋右腿均可，另一侧保持准备位。同侧可重复，换侧前必须完整回 A；单肢、同侧手腿、四肢同时伸展均不能算有效 B。

| 难度 | 基础分 | 保持分上限 | 有效保持目标 |
| --- | ---: | ---: | ---: |
| 轻松 / Easy（原说明中的「简单」） | 85 | 15 | 3 秒 |
| 标准 / Medium | 80 | 20 | 5 秒 |
| 挑战 / Hard | 75 | 25 | 7 秒 |

`实时分 = 基础分 + 保持分上限 × min(有效保持秒数 / 目标秒数, 1) − 姿态扣分`

- 进入 B 立即获得基础分；活动手腿连续稳定 **0.12 秒**后才累计有效保持时间。
- 首次 A 和 B 分别确认 0.20 秒；离开 A 确认 0.08 秒；离开 B 确认 0.15 秒；回 A 确认 0.16 秒。
- 抬伸进度进入阈值为 Easy 0.38、Medium 0.44、Hard 0.50；维持阈值降低 0.13，进度采用 60 毫秒滤波。
- A 的双臂高度至少为臂长的 0.78、肘角至少 150°。腿部膝角 60°–120°、大腿偏离竖直不超过 35°、小腿偏离水平不超过 35°。保持和离开准备位使用包内较宽容的滞回阈值。
- 过渡停滞 2 秒或总计超过 12 秒时取消未完成尝试；回收途中同侧重新伸展可以接续原轮次，不重复给基础分。
- 无新动作包、快速摆动、暂停和回位不增加保持时间。短于 80 毫秒的数据间隔保留显示和稳定窗口，但不增加时间；持续缺失约 350 毫秒取消当前轮次，恢复后重新确认 A。
- 完整回 A 才结算本轮最高分，并保存同一帧扣分原因。本次成绩只统计已完成的轮次。

四项姿态扣分分别为手臂／腿部水平方向偏角、手臂／腿部竖直仰角。水平 12° 内免扣，60° 达单项上限；竖直角绝对值 10° 内免扣，45° 达单项上限。每项线性计算、保留两位小数，最多 1.25 分，总计最多 **5 分**。例如手臂偏低 25° 扣 0.54 分。保持分与姿态扣分分别计算。

评分读取约束修正之前的输入；模型显示纠正不会代替用户完成动作。约束的角速度限制为躯干／骨盆 120°/秒、头颈 160°/秒、手脚 240°/秒、其他主要关节 300°/秒，并保留原包的异常帧拒绝逻辑。

## 教练、画面与迁移边界

录制 JSON 原样复制到 `Resources/DeadBugDelivery/dead_bug_recorded.json`。教练采用 7–10 秒伸展、10–12.5 秒回位，在 B 端点额外保持 7 秒，再演示另一侧的解剖镜像。用户计分独立于教练时钟；不同难度仍使用各自的有效保持目标。

新场景显示录制教练与实际输入模型两个预览窗，四个肢体标签共用字号和缩放。圆环音符跟随用户动作进度，确认 B 时显示 HIT，未完成尝试中止时显示 MISS。材质与颜色锚点网格在运行时复制，避免修改共享资源；相机取景在骨骼更新与约束之后执行。

副本中的原游戏流程保持停用，并移除会触发全局输入启动器的旧 RhythmModeController，避免重复接收和重复评分。交付包的练习菜单、回放／录制入口、通用控制器和整套 SDK 没有覆盖到现有工程；本次将死虫核心训练规则接入独立游戏流程。

原始说明保存在 `Documentation/死虫场景导入与使用说明.md`，来源和校验值见 `Documentation/DeliveryProvenance.json`。五个核心实现除命名空间隔离、录制资源路径与镜像帮助函数名称外，与交付包一致；录制 JSON 字节完全一致。

- 仿真输入和 UDP 测试发送器只在临时验证项目中，未加入主项目或交付场景。
- 主项目运行时与编辑器代码编译通过；原有 10 个场景、共享脚本和此前鸟狗迁移文件校验值不变。
