# 模块 01：播放时间轴与动作教学流程

> **旧版实现拆解，已废止。不要作为执行要求。** 患者流程和播放设计见唯一权威 [12 号方案](12-keep-video-observation-and-coach-product-spec.md)；执行提示词见 [13 号](13-codex-execution-prompts.md)。

## 目标

让播放时间轴稳定带患者学会当前康复动作的基本做法：先讲解和示范，再边播放教练动作边在正确时机提示患者要做什么。非处方默认 1 组 4 次；处方训练量必须来自处方通路并优先于默认值。保持已有动作包、男女 Practice 场景、暂停/继续/跳过/主动结束、安全停止和追踪断连语义。

## 需求

1. 播放控制器是唯一的练习时钟和 repetition 计数来源。姿态阈值、高亮、震动、语音播放完成回调不能要求 `AdvanceToNext`、等待合格或改变计划次数。语音 cue 由播放阶段事件触发；阶段时长由播放流程预先安排。
2. 动作流程包含 `动作讲解/示范 → 准备及倒数 → 往返动作阶段 → 次数结算 → 下一次/组间休息 → 完成`。具体 phase 与已录制动作帧对齐，不重写已有动作包的顺序和动画。
3. 用户看到真实训练量：非处方默认 `第 1/4 次` 到 `第 4/4 次`；处方模式显示处方次数。每次从动作包定义的完整往返完成后计数，不按导入片段数重复计次。没有达标不能卡住播放。
4. 开始前给动作解释和完整示范；动作播放时按教练当前正在做的阶段及时提示，例如抬起/伸展开始时告知患者具体该动哪个部位，保持/回程时给对应提示。患者应能听懂“现在要做什么”，不能只听到抽象鼓励或数字。
5. 原有提示、准备语、倒数、停顿和音频速度必须保留。阶段提示由播放轴在教练对应动作节点发出。播放轴是唯一推进者，但语音窗口是播放编排的一部分：必须在阶段/保持/休息时长中预留完整原速语音；如果当前动作片段太短，就调整编排时长或加入明确语音窗口，不能靠删词、加速、剪尾或省略倒数。不得把姿态评分接回播放推进。语音完成回调可以标记该 cue 已播完，但不能改变 repetition 计数或等待患者达标。
6. 暂停冻结动画/计时并暂停音频；继续从相同位置恢复，不重复计次。保留现有主动结束、安全停止和追踪断连语义。
7. phase 事件如确有需要，可扩展已有 `CoachSegmentEvent` 表达动作和当前 repetition；先满足行为，再用最小事件改动，不建立多套互不兼容的状态机或评分窗口链。
8. 当前代码已有 phase/hold/rest 自动推进与 `CoachEventBus`；先追踪 `SegmentedCoachController` 与 JSON 课程路径实际行为，保留无评分 gate 的边界。不得整体重写控制器。

## 重点验收

- 非处方训练按默认 1×4 完成；处方训练量按处方执行。动作正确与否都不改变播放推进/计次。
- 追踪数据不可用、姿态没有到绿显阈值、语音播放器未订阅时，播放仍走完。
- 暂停/继续和跳过当前 phase 不丢失或重复 repetition；跳过和主动结束结果能区分。
- 动作口令在对应动画阶段播报；每次需要患者跟做的动作都要有对应 cue，不得只在同一 segment 第一次出现时播一次通用提示。播放轴按动作编排推进，语音完成回调不能改变动作次数或评分状态；原有语音和倒数按原速、完整保留。音频资源缺失不能卡死课程，但必须报告缺少哪条提示及该动作教学不完整。
- 练习结束出现“我已学会，进入游戏模式”和“还需要学习，再练一次教练模式”两个用户选择；不由分数替患者作决定。
