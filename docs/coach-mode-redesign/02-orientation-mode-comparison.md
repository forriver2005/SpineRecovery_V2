# 模块 02：教练与用户朝向模式对比

> **旧版实现拆解，已废止。不要作为执行要求。** 朝向定义唯一来源是 [12 号方案](12-keep-video-observation-and-coach-product-spec.md)：默认 A，A 为教练持续跟随用户且画面中两者同向，B 为教练固定而用户显示模型旋转对齐。

## 目标

教练模式开始前让患者选择一种显示方式，方便对比哪种更容易看懂动作。两种模式含义固定、互斥，不能把上一次模式残留的旋转叠加到下一种模式。

## 两种模式

**A：教练跟随用户。** 用户模型保留真实追踪方向；训练中教练模型持续跟随用户模型的朝向转动。方向变化应平滑呈现，避免追踪抖动造成教练来回跳转。保留教练动作原有的观察角、俯仰和动作可读性；不能直接覆盖完整旋转而破坏演示姿势。

**B：用户模型对齐教练。** 教练维持场景原本的教学视角；画面里的用户模型旋转到与教练一致。此模式只改变用户模型的展示朝向，不改变实际传感器数据、动作判断或身体追踪方向。

选择在教练训练开始前完成，默认选 A；用户可以切换到 B。训练开始后模式固定；如需比较另一种模式，返回开始前重新选择并开始。选择控件应明确显示 A/B 的含义和当前选项，不用难以理解的“旋转开/关”文字。

## 实施要求

1. 先追踪 `PracticeSessionController` 当前方向对齐、准备位检测、共享显示参考系、卧位展示以及退出时恢复原朝向的完整流程。以场景当前画面为基准，不改变方向识别和动作判定。
2. A 模式仅旋转教练显示朝向去跟随用户显示朝向；B 模式只旋转用户显示模型去匹配教练。选择 A/B 时先还原两边记录的原始显示旋转，再应用目标模式，禁止累加旋转。
3. 保留卧位动作的现有观察角、头脚方向处理和躯干展示平面处理。若这些现有校正与 A/B 变换互相冲突，先说明具体动作与画面，不悄悄删掉其中一项。
4. 用户模型或传感器的实际姿态数据不因展示变换而改写；姿态评分、红绿高亮、震动和训练记录仍使用当前正确的数据坐标。
5. 退出、重开、用户切换动作或销毁 Practice 场景时，恢复进入前保存的展示旋转。方向输入暂时无效时保持最后一个稳定显示方向，不引入新的安全停止条件。
6. 开始界面选择需覆盖所有当前可用的教练 Practice 动作；若某种动作/场景无法支持某一模式，应说明原因并给出一致的降级显示，不能默默切换选项。
7. 游戏模式不增加该控件，不改变游戏模型方向。

## 文件边界与验收

主要检查 `PracticeSessionController.cs`、`MobileCoachControls.cs` 和当前已接入的 Practice 场景。先盘点再改，尽量复用现有方向对齐实现；避免重写追踪或评分。

交付时至少能在同一动作场景中开始 A、结束后开始 B，并直观看到：A 中教练跟随用户转向；B 中教练视角固定且用户显示模型与教练一致。重点检查死虫、鸟狗和至少一种其他已接入动作，并检查重新开始后没有残留旋转。仅做证明这两种效果和恢复行为所需的定向验证，不构建大型测试矩阵。
