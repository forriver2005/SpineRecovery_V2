# 模块 03：持续动作观察、绿色反馈与震动

> **旧版实现拆解，已废止。不要作为执行要求。** 患者端只设计正确部位绿色高亮；未达标/未知不亮绿，纠错依赖具体语音，不设计红色错误列表或红色高亮。产品细节唯一来源见 [12 号方案](12-keep-video-observation-and-coach-product-spec.md)，执行提示词见 [13 号](13-codex-execution-prompts.md)。

## 目标

教练动作播放时持续观察患者动作，不显示分数，不按播放轴的某个特定时刻开启评分窗口。已有动作判断独立运行；在当前规则判断正确时，对应身体部位绿色高亮并给一次触觉确认。未达标时不显示绿色，并以动作/部位语音做可执行纠正；错误红显不是患者体验要求。

## 行为要求

1. 覆盖所有当前已接入的教练动作，包括死虫、鸟狗、臀桥、腰背及其他 Practice 动作。每个动作沿用自己的现有判断、目标部位和有效追踪要求；不只实现死虫/鸟狗。
2. 本轮不改任何动作的数值阈值、几何定义、滞回、动作阶段或临床含义。绿色必须来自该动作现有正确条件（有 `shouldClear` 就使用它），不能用 `!shouldActivate` 代替；红色错误阈值与绿色正确阈值之间的滞回区不亮绿。动作已有单独正确判断时沿用该判断。
3. 绿色只能表示现有规则确认该部位正确。未追踪、数据过期、几何不可计算、当前动作不涉及或当前阶段不适用的部位，不能因“没有红色”而显示绿色，也不能触发正确震动。
4. 绿色、震动和任何现有正确状态必须使用同一判断结果，不各自新建一套相似但不一致的阈值。跟练画面不显示实时分数、分段通过/失败或评分进度。
5. 正确绿显、纠正语音和震动均为反馈链路；它们不能推进、暂停、延长或阻止播放，也不能改变计划次数。输入丢失只影响反馈可用性，保留既有断连/安全停止规则。
6. 正确部位按各自现有正确状态分别显示绿色。多目标动作等本次动作涉及的所有目标部位都达到正确状态后，对应 tracker 同步震动一次；单目标动作对应 tracker 震动一次。同一正确状态只触发一次，不能反复震动。
7. 先修复全绿时的显示分支：显示正确部位不能依赖错误区域集合非空。场景启用模型表面高亮时，只要正确颜色表非空就必须调用表面高亮；错误和正确可同帧分别显示在不同部位，但不能把错误区域当作正确震动对象。
8. 震动调用沿用 tracker 部位映射。所有目标 tracker 必须在同一个触觉事件内同时发出请求；禁止逐个 coroutine 排队或串行等待。检查 HTTP/设备实际发送路径，证明请求是并发发起的，并测量或实测设备启动时差。若底层协议不支持同步启动，明确列出需要的服务/固件能力，并报告此项未完成；不能把“同一 Update 调用”直接宣称为设备同步。震动端点缺失或请求失败时，绿显仍可工作、播放继续，震动不成为播放 gate。
8. 游戏模式的分数条、分数阈值、震动、碰撞和场景不改。

## 必须拆开的状态

当前代码里的 `guidancePartsToHighlight`/`confirmedGuidanceParts` 是旧的纠正区域状态，不能继续同时承担正确部位、绿色显示或正确震动。实现必须明确分开至少三类状态：

- `wrongParts`：当前有效追踪下持续达到现有错误进入条件的区域，供红显和纠错提示使用；
- `correctParts`：当前有效追踪下持续达到现有正确清除条件的区域，供绿显和正确反馈使用；
- `unknownParts`：没有数据、过期、不可计算或当前动作不适用的区域，不触发红/绿/震动。

`correctParts` 不能从错误状态为空推导，不能只在错误状态非空时才调用高亮。全部目标正确而错误状态为空时，绿色高亮仍必须可见。内部错误可视化不属于患者交付要求；患者验收只看正确时绿显、未达标不绿、错误时有可执行纠正、未知不误判。

死虫/鸟狗的 `shouldActivate` 是错误进入条件，`shouldClear` 是正确清除条件；两者中间的滞回区不属于 `correctParts`。现有确认/释放时长可以继续用于防抖，但不能改变这两个条件的含义。

## 实施前的逐动作盘点

实现者先做一张简短清单：动作、当前红色/正确判断来源、可判断的身体区域、追踪有效性判断、现有震动路径。此清单用于避免漏掉动作，不要求新增协议或逐次成绩记录。

如果某个已接入动作没有任何可复用的错误/正确判断，或现有数据结构无法区分“有效且不满足错误条件”和“没有数据”，不得编阈值补齐。先把动作和代码路径列清楚，并向产品负责人确认下一步；在此之前不可将其静默漏出本次覆盖范围。

## 文件边界与验收

主要查看现有 `PoseScorer`、`PoseGuidanceRuntime`、动作专用指导代码、高亮组件和 `TrackerHaptics`。只改实现 wrong/correct/unknown 分离、绿色反馈和去重触觉实际需要的文件及场景，不改播放控制器、训练结果协议或游戏代码；若接口缺失，先报告跨模块需求。

验收用死虫和鸟狗作为重点样例，并至少抽看臀桥或一种腰背动作：处于现有错误阈值与正确清除阈值之间时不绿；达到正确清除条件后正确部位绿显。全部做对时即使没有错误状态也必须能看到绿色。死虫双目标均做对后左臂、右腿 tracker 同步震动一次，不能此起彼伏；单一目标动作只震对应 tracker 一次。做错时不亮绿并播放可执行纠正；无效追踪时不误绿、不把“未知”当错误；无论动作是否做对，播放轴都按计划走完。只做能证明这些接线和同步行为的少量验证。
