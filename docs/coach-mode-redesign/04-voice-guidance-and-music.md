# 模块 04：语音教学、提示优先级与背景音乐建议

> **旧版实现拆解，已废止。不要作为执行要求。** 语音和音乐决策唯一来源见 [12 号方案](12-keep-video-observation-and-coach-product-spec.md)：保留已有原速语音和完整倒数，本轮默认无 BGM；患者端错误提示用具体语音，不设计红显。执行提示词见 [13 号](13-codex-execution-prompts.md)。

## 目标

语音是教练模式的教学主体之一。它要帮助患者知道“动作是什么、现在做哪一步、怎样呼吸、哪里要调整、何时做对”，并按正常自然语速完整播放。背景音乐可作为可选陪伴层，但不能遮盖康复指导。

## 实施前必须做的语音盘点

阅读 `VoicePromptManager.cs`、`CoachEvents.cs`、场景里的 VoicePromptManager 序列化引用和 `Assets/Audio/VoicePrompts`。当前可见的既有资源/职责包括：教练介绍、用户模型介绍、`ReadyCountdownShort`、调整姿势、保持、`2`/`1`、开始、下一动作、`deng`/`ding`、阶段动作包 `voiceClip`/`voiceClipName`。先做一张旧 cue → 实际教练动作节点 → 实际资源 → 当前调用点的映射。检查所有 Practice 场景的 `voiceClip` 和动作包 `voiceClipName` 是否为空；资源仍在项目中不等于动作教学已完成。

素材真实内容不能从文件名推断：尤其检查 `ReadyCountdownShort.mp3` 是完整倒数还是单句提示；当前资源目录未发现明确名为 `3.mp3` 的语音，但已有 `1.mp3`、`2.mp3`。若既有序列缺数，不能默默删除倒数或假称语音完整；保留视觉倒数节拍，并把需要录制的缺失语音作为明确素材依赖。不得自行通过加速播放补时长。

## 语音内容与时机

| 类别 | 主要内容 | 时机 |
|---|---|---|
| 训练/动作介绍 | 当前康复动作的动作名称、患者要做什么、起始姿势、关键注意点和必要安全提示 | 动作专属讲解在正式跟练前播放，之后教练完整示范；通用教练/用户模型介绍不能代替动作讲解 |
| 准备与倒数 | 保留当前准备语、数字、数字间隔、“开始”和现有视觉倒数 | 保持现有流程和调用时机；不删、不压缩，也不擅自增加每次 repetition 倒数 |
| 阶段提示 | 对应教练当前动作的清楚指令，例如抬起时提示“抬左臂和右腿” | 动画刚进入抬起/伸展阶段时触发，不能等完整片段播放完才说 |
| 个体纠错 | 当前未达到正确条件时，一条可执行的动作/部位提示 | 错误稳定成立后按节流规则播报；正式跟练期间不能被语音 phase 独占逻辑静默拒绝。患者反馈以语音纠正为主，不要求错误红显 |
| 正确反馈 | 正确部位绿显 + 对应 tracker 触觉确认；可有简短肯定语音 | 达到既有正确条件时触发；滞回区不能算达标，肯定语音不得盖住动作方向 |
| 休息/衔接/鼓励 | 下一动作、休息提示、低频鼓励、动作完成提示 | 当前组间/动作转场窗口 |
| 安全提示 | 停止或按既定安全流程处理 | 最高优先级，可打断普通语音并触发既有安全监督 |

每个已接入动作必须有动作专属内容映射，至少对应动作开始、保持/回程、可执行纠错、正确状态反馈。口令需能从已核实的动画/动作包说明中得出；涉及康复姿势、安全、呼吸或疼痛处理的内容必须来自已有审核材料或临床审核稿。缺少录音时列出逐动作录音待办和拟录文案，等待专业审核/录制；不能把通用“请根据教练演示调整动作”冒充动作口令，也不能报告该动作教学语音已完成。

## 节奏与优先级

- 原音频始终以原速、原音调、完整尾音播放；不得删去已有 `keepStill`、倒数数字、`start`、`nextAction`、动作片段语音、介绍、节拍或已有鼓励提示。
- 语音 cue 跟随教练当前动作节点，不按固定“每次重复一句”的模板硬套。抬起/伸展口令要在对应动画开始时触发，不能只在片段结束的 hold 阶段才出现。播放编排必须为完整原速语音预留时长；不能为了赶动画压缩片段、减小间隔、提高 `AudioSource.pitch`、剪尾或静默丢 cue。质量结果不控制播放轴。
- 暂停时音频与播放时钟一起暂停，恢复原位置；跳过/安全中断只取消当前 cue，不将过期排队语音带到下一动作。动作质量观察不控制语音时序，也不要求语音等待评分。
- 安全提示优先级最高；准备/倒数、当前动作方向和必要呼吸提示不可被普通纠错、肯定或鼓励盖住。纠错/正确状态与语音忙碌时，按现有队列/过期策略处理，不能让旧 cue 穿越到下一动作。
- 保持现有自然停顿、数字间隔、提示顺序和语速。变更前先对照实际 AudioClip、调用点和阶段完成条件；不得将任意语音加速或把倒数省略。若没有动作特定口令素材，列为康复内容/录音待办，不由 Codex 编造医学指导。

## 背景音乐决策

产品建议：本轮不新增背景音乐、音量控件或混音系统。教学指令是康复动作学习的核心，背景音乐可能影响听辨；目前也没有确认适合医院场景、已授权的音乐素材。保留以后评估的空间，不复用游戏 BGM。语音引导与用户明确要求的绿显/震动优先交付。

## 文件边界与验收

主要负责 `VoicePromptManager.cs`、动作 cue 映射、确需新增的音频引用，以及为在动作开始节点触发 cue 所需的最小播放事件接线。允许与模块 01 协调调整 cue 时机和阶段编排，但不得修改动作判定阈值、绿色反馈或结束路由。

验收要求：逐项听/检查旧资源映射和顺序；旧 cue、倒数和间隔没有丢失，原速完整播完；动作开始节点听到具体方向口令；错误状态能发出可执行纠正，且不会被静默拒绝；正确状态有绿色和触觉反馈；语音/反馈不由分数推进。暂停/恢复不重播，普通提示不盖住倒数或动作方向。背景音乐不新增。无法试听时明确记录未验证，并将没有动作专属录音的动作列为未完成。
