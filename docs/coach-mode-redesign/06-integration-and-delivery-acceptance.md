# 模块 06：集成与交付验收

> **旧版集成/验收拆解，已废止。不要作为实现要求。** 产品验收唯一来源见 [12 号方案](12-keep-video-observation-and-coach-product-spec.md)，执行和少量代表路径见 [13 号](13-codex-execution-prompts.md)。

## 集成顺序

按依赖顺序逐个合入：

1. 模块 01 保证播放链是唯一主时钟：讲解/示范、准备、倒数、动作阶段、次数、暂停和安全终止连续可控。
2. 模块 02 接入开始前朝向选择：默认 A，教练持续跟随用户；B 为用户显示模型对齐固定教练视角；两种模式不叠加且可恢复。
3. 模块 03 让全部现有教练动作沿用自己的连续判断，正确部位绿显；多目标部位达标后，对应 trackers 同步震动一次；质量不 gate 播放。
4. 模块 04 盘点并恢复所有既有语音/倒数/停顿/节拍，播放阶段事件触发对应提示，播放时钟按预设推进且不等语音完成回调；音乐本轮不新增。
5. 模块 05 接上正常完成后的两个去向，保持中断路由和游戏模式原行为。
6. 本模块只修真实接线、状态残留和兼容问题，不重写架构。

多对话协作时不要在同一个可写 checkout 并发改代码。独立 worktree 必须包含当前 `Coaching` 工作树状态，合并前逐文件检查差异，保留用户和前序改动。

## 交付验收路径

1. 死虫：讲解和示范完整，非处方默认 1×4；动作开始抬起时有左臂/右腿的具体提示；当前正确清除条件达到后对应部位绿显，左臂与右腿都正确后两个 tracker 同步震动，错误逻辑仍红显，播放不等评分。
2. 鸟狗：主动肢体、支撑肢体、躯干的现有正确清除条件均能反馈；错误条件和正确条件之间的滞回区不误绿；无效追踪不冒充正确；不改现有动作数值。
3. 其他已接入动作：至少抽查臀桥或腰背动作，确认不是只为死虫/鸟狗写的特例，且沿用该动作现有正确目标条件，绿色和震动来自同一状态闭环。
4. 朝向：开始前默认 A，同一动作开始前可切换 A/B 对比画面；A 中教练随用户转向，B 中用户显示模型与固定教练对齐；重开后没有旋转残留。
5. 语音：已有讲解、准备、完整倒数、开始、保持、动作提示、错误纠正、正确反馈、下一动作和结束音逐项核对；动作提示在动画开始节点出现；原速完整、不删倒数、不为追时间加速；暂停恢复不重复或吞掉关键语音。只有通用“请根据教练演示调整动作”或片段结束后才出现的提示，不算通过。
6. 结束分流：正常完成显示两个选择，分别进入游戏或再来一次教练；提前结束、安全停止和断连不误显示；游戏模式分数、场景、震动和结果不变。
7. 鲁棒性：无追踪、短暂丢失、haptic 端点缺失、可选语音缺失时，播放不死锁；已有真正断连和安全停止仍按原规则。

无法接入真实 tracker 或医院音频时，报告为模拟/静态未验证，不宣称真机通过。只做上述路径需要的定向验证，不建立大型测试矩阵或额外 gate。
