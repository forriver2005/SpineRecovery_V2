# 2026-10-30 教练流程改造执行方案

本方案基于12号产品方案、13号执行提示词，以及用户2026-10-30实测后的口述要求。它是后续实现顺序和验收口径，不替代12号产品需求。

## 一、已确认的目标行为

### 1. 讲解和示范合并为一个同步阶段

点击开始后，教练边做动作边讲解，动作和语音尽量同相位发生。左侧显示当前动作独有的“动作技巧”文字卡，文字用于帮助患者理解发力位置、动作特点和注意点，不复述整段讲解语音。

六个动作分别维护自己的技巧卡：

| 动作 | 讲解文字方向 |
| --- | --- |
| 死虫 | 核心稳定、对侧手脚交替、缓慢控制、自然呼吸 |
| 鸟狗 | 腹部稳定、对侧手腿伸展、背部保持自然、伸展后回位 |
| 臀桥 | 臀部发力、双脚稳定、抬起和回落受控、避免借腰发力的提示仅在现有判断能支持时使用 |
| 卧位猫式 | 背部小幅活动、动作轻柔、跟随示范拱起和回到支撑 |
| 侧桥 | 当前支撑侧、躯干撑起、骨盆受控回落、保持舒适 |
| 卷腹 | 上背小幅卷起、颈部舒适、缓慢回落、自然呼吸 |

### 2. 跳过讲解

“跳过讲解”是独立于正式动作分段的控制：

1. 取消当前讲解语音队列；
2. 停止当前同步示范；
3. 使旧示范的完成回调失效，防止旧协程在新流程中再次触发倒计时；
4. 清理教练展示状态和过期提示；
5. 进入原有准备语、完整准备倒数和正式训练；
6. 从第1次“带着做”开始。

跳过不调用普通 `AdvanceToNext()`，也不调用会结束会话的 `StopPractice()`。

### 3. 八次训练结构

总次数为8次：

- 第1～4次：教练带着做，保留当前动作阶段的方向、保持/呼吸和回位提示；
- 第5～8次：患者自主完成，保留必要的动作提示，但不播放语音数字倒计时；
- 有处方时继续沿用处方的组数/次数优先级；无处方时默认1组8次，待用户确认这一优先级后锁定。

两段都继续显示当前次数、阶段和目标侧别。观察、绿显、触觉和追踪状态不能阻止播放、计次或结束。

### 4. 保持倒计时和动作提示音

- 保持阶段显示全屏或主区域淡化后的 `3、2、1` 画面；保持阶段的“请保持住”可以和倒计时嘀声同时播放。
- 抬起/伸展目标部位时播放一次短嘀声；回到准备位时播放一次短嘀声。
- 非保持阶段不显示保持倒计时画面。
- 正常自主阶段不播报数字倒计时，数字只由画面承担。
- 原有准备语、完整倒数、数字间隔、尾音、自然语速、pitch和动作承重时长全部保留；新提示音不能通过剪短旧音频或延长动作保持来塞入。

## 二、代码实施顺序

### 阶段 A：先修讲解状态机和跳过

1. 在 `PracticeSessionController` 建立本次讲解会话代次和一次性完成保护。
2. 在 `SegmentedCoachController` 增加独立的取消/跳过示范入口，停止旧 `lessonRoutine`，回到准备姿势，并让旧 `completed` 回调失效。
3. 在 `VoicePromptManager` 增加只取消当前讲解序列的接口，不能误停正式训练音频。
4. 在正式 Practice Canvas 和 `MobileCoachControls` 接入“跳过讲解”按钮，只在讲解/同步示范阶段可见。
5. 将讲解和示范改成一个受同一会话代次控制的播放轴，避免第二次重练时旧协程再次调用倒计时。
6. 先用死虫代表路径复现：第一次开始、点击跳过、完成一次重练、再次进入讲解；确认没有重复语音、重复示范、提前倒计时或黑屏。

### 阶段 B：建立 8 次和带做/自主两段节奏

1. 保留处方训练量入口，增加无处方默认8次配置。
2. 把 `currentRepeat < 4` 定义为带做阶段，把 `currentRepeat >= 4` 定义为自主阶段；侧别仍按照动作既有交替规则计算，不复制第1～4次的计数文案。
3. `CoachSetProgressUI` 显示 `1/8` 到 `8/8`、准备/动作/保持/回位和当前目标侧别。
4. 带做阶段使用每个动作的方向、保持/呼吸、回位节点；自主阶段删除数字语音，只保留动作执行所需的短提示。
5. 让保持倒计时 Overlay 只由 `HoldAtSegmentEnd` 的核心保持阶段驱动，回位段不显示保持倒计时。
6. 播放轴、语音轴、观察轴、触觉轴分别推进；任何一轴失败都不能阻塞其它轴。

### 阶段 C：六动作讲解技巧和提示音

1. 为六个动作各建立独立的技巧文本配置和正式场景引用。
2. 讲解阶段左侧显示动作技巧卡，示范结束或跳过讲解时隐藏。
3. 为动作目标开始和回位建立短嘀声节点；保持段接入画面 `3、2、1` 和保持嘀声。
4. 新增素材继续使用统一晓晓普通话静态音频；运行时只播放打包后的 WAV/MP3。
5. 不替换现有倒数、数字、尾音和休息录音；新音频只添加到新节点。
6. 对每个动作检查“台词说的部位/方向”和代码实际识别部位一致；不为无法判定的方向编造纠错。

### 阶段 D：收窄触觉目标

1. 在 `PoseScorer`/触觉映射层把手臂目标收窄到小臂，把腿目标收窄到小腿。
2. 腰部只保留确认后的腰/腹部 tracker，移除胸部 tracker；如果最终确认胸部也属于腰部目标，则单独调整映射表。
3. 保持同一逻辑组事件、去重和并发 HTTP 发起方式；不把单独请求响应成功作为播放 gate。
4. 用模拟驱动验证同一动作目标同时正确时只产生一次组事件，非目标和未达标不震。

### 阶段 E：代表路径和截图验收

只做代表路径，不扩成大矩阵：

1. 死虫：讲解技巧卡、跳过讲解、第1/4次带做、第5/8次自主、保持3/2/1、回位嘀声、回位清绿、完成页。
2. 鸟狗：同步讲解示范、左右目标侧别、一次暂停恢复和第8次完成。
3. 臀桥：保持倒计时和腰部触觉映射。
4. 卧位猫式、侧桥、卷腹：确认各自技巧卡、动作节点提示和8次节奏接线。
5. 截图文件按阶段命名并保存到 `.codex/coach-flow-screenshots/`，每张注明是 Unity 模拟验收还是 APK 真机截图；没有设备时不冒充真机截图。
6. 最后重新打包 APK，并记录构建结果、哈希和是否有 Android 设备安装启动证据。

## 三、验收口径

必须实际看到：讲解时教练同步做动作、左侧独立技巧文字、跳过后直接进入带做、第1～8次状态、保持倒计时淡化画面、动作/回位嘀声节点和完成分流。

必须实际触发或记录：目标正确时仅目标部位绿显、目标追踪失效时不绿、组触觉事件只发一次、播放不因追踪或 HTTP 失败而停止。

只能记录为代码已接入但未完成患者验收：完整音频听感、真实 Android 外放、实体 tracker 有效性、实体马达起振和真实网络下的同步差。

仍需康复专业确认：六个动作技巧卡中的发力/稳定表述，以及新死虫的“举起后放下到位”幅度、新鸟狗派生示范和到位窗口。专业确认不能用模拟通过替代。

## 四、当前必须确认的两项边界

1. “腰部”是否只指腰/腹部 tracker；当前旧映射是胸部+腹部。
2. 8次是否仅作为无处方默认值；有处方时是否继续按处方次数执行。

在这两项确认前可以完成讲解状态机、技巧卡、8次显示和倒计时框架，但触觉映射与训练量入口不应最终锁死。
