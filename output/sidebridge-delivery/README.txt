侧桥交付评分接入说明（2026-10-31）

范围
SideBridge_RingBridge_Dynamic 与 SideBridge_RingBridge_Hold30。
沿用现有左侧录制动作、场景视觉、音乐、处方次数和教练时间线；30 秒模式仍需抬起、保持、完整放下。

接入内容
1. 骨盆相对支撑肘—支撑脚水平投影基线的高度，以肩中点到双脚中点距离归一化。
2. 躯干角改为肩中点—骨盆—双脚中点；腿部采用双膝平均角度。允许录制中的屈膝和分脚，不要求双脚重叠。
3. 动作质量沿用交付包的躯干 40%、支撑 30%、膝部 20%、肩部侧向排列 10%，支撑项包含上臂朝向和肩肘水平偏移。
4. 采用 A、抬起、B、放下四状态和持续确认、峰值相对回落与支撑丢失检测。侧桥数据超过 0.35 秒未更新时不继续计分。
5. 使用现有游戏实际录制周期的 A/B 参考，并按用户骨架比例重定向。原用户骨骼在参考采样返回前完整恢复；不引入额外 VMC 映射器或直接修改用户关节的约束脚本。

针对游戏与误差测试的适配
1. 交付包的 B 识别门槛（简单 15%、标准 35%）用于阶段识别。计时另要求有意义的高位幅度和当前教练幅度匹配；不能把识别到 B 当作完成处方。
2. 保持质量阈值为简单 35、标准 50、困难 60；质量容差倍率 1.6、1.25、1.05。困难是对交付包两档难度的游戏扩展。各档动作速率、组数和教练时长相同。
3. 起始低位最多采集 0.2 秒零点偏移，每个录制周期单独处理。只在教练低位、用户侧向支撑且形状接近低位参考时学习；补偿最多为该录制周期 A/B 高度差的正负 50%。录制高度差较小，多个腿部传感器的轻微角度误差可造成较大的归一化零点偏移。只平移零点，不学习或放大用户的最大动作幅度；高位起步不可当成低位。
4. 动作进度先滤波后截断；稳定性平滑有符号速度，避免将正负抖动的绝对速度平均成持续运动。一次被排除的跳点恢复后不残留虚假的速度尾巴。
5. 当前录制高位本身有超过 8% 的起伏；相对峰值下降还须离开高位合格区才进入放下，防止正常演示提前结束保持。
6. 保持最多容忍 200 毫秒短暂异常以保留连续性，异常帧不加时。较长中断不拼接两个短保持；30 秒之外的抬起时间不补入保持目标，未完整放下不计合格次数。
7. 实时分与结算共用同一份有效保持证据，移除了侧桥结算中重复且标准不一致的计时观察器。既有百分制总成绩公式与五项用户结果字段保持不变。
8. 独立硬门槛阻止站立、错误支撑侧、支撑臂明显偏离、严重肩髋扭转等情况被其他高分项目抵消。

验证方式
Unity 2022.3.62f3c1，独立项目副本，真实录制 Humanoid 动画与独立用户骨架，合成输入包。
SideBridgeScoringVerification.Run：状态边界、真实录制、两模式三难度、30/60/120 FPS。
TrainingToleranceSceneVerification.RunSideOnly：两模式三难度，每组覆盖 36 种实际使用情形。
包括 80%/90% 幅度，350/500 毫秒跟随延迟，3/5 度抖动，1 帧/100/300 毫秒缺测，100 毫秒异常姿态，髋/腿/支撑臂正负 8 度偏差，幅度与偏差叠加，朝向与体型缩放，半程、错误支撑、错误方向、高位起步、未放下、提前下降及无骨骼心跳。
baseline.txt 为旧评分的同类测试结果；side-final.txt 为最终侧桥结果；boundaries.txt 与 timing-boundaries.txt 为边界报告。
hip-regression.txt、rhythm-regression.txt、six-game-vmc.txt、difficulty-dose.txt 为合并 main 后的其他游戏与输入链路回归结果。

main 合并
保留 main 原有教练动作库、练习入口与场景；合入 Gaming 的六个游戏依赖。
合并时排除同一游戏接收器上的第二个 SlimeVR 数据适配器，避免覆盖游戏帧序号；练习适配器收到真实骨骼包时更新新鲜度时间。

测试边界
这些是可复现的软件回放和本机 UDP 测试，不等同于真实佩戴或临床有效性验证。真实设备还应复测绑带松紧、校准姿势与单只追踪器丢失；若上游继续发送已冻结的完整骨骼数据，当前接口没有独立的每只追踪器置信度，无法仅凭包是否到达识别该情况。
